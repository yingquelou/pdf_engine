# PDF 2.0（ISO 32000-2）差异摘要
> 事实层｜职责：登记 PDF 2.0 差异立场与标准版本引入史。｜禁止：排期、阶段归属、实现状态。

**本库当前立场**：

- **Reader**：容忍 2.0 文件头（解析为已知版本、记 warning 后继续，不拒绝），证据 tests `reader_accepts_pdf_2_0_header`、`version_parsing_recognizes_2_0`（types.rs `PdfVersion::parse`/`from_name`）。
- **Writer**：输出区间 1.0–1.7，显式拒绝 2.0，证据 writer/ `SUPPORTED_OUTPUT_VERSIONS` + `validate_output_version`，测试 `writer_rejects_unsupported_version`。
- **口径**：**语法层接受 `%PDF-2.0` 文件头不等于本库是自声明的 conforming PDF 2.0 读写端**。本库的符合性声明对象始终是 ISO 32000-1:2008；对 2.0 新增语法（加密修订 5/6、UTF-8 文本串、`/AF` 扩展挂接对象等）只在读端做到「不因此拒绝解析」，不据此宣称支持 2.0。
- 本节仅作**远期评估依据**，列出的条目**不进入当前开发阶段**（全部视同 P3）。

**主要差异点**（依据 ISO 32000-2 公开资料与官方发布记录；凡未能在本地 `docs/PDF32000_2008.pdf` 抽取文本或权威发布页核实的细节，一律显式标「待核」）：

1. **加密**：AES-256 正式纳入标准算法族，对应**修订 5（AESV3）与修订 6（强化密钥派生）**，两者的公钥/标准安全处理器版本 `/V` **均为 5**（`/V` 6 不是 32000-2 的加密版本取值）。RC4（修订 3/4）与 `/V` ≤ 4 组合在 2.0 中属弃用/兼容保留。另有 unencrypted wrapper document（未加密包装层包裹加密文件）机制。
   - 补注：AES-GCM 属后续增补文档（据报为 ISO/TS 32003:2023，取 `/V` 6 / 修订 7），**来源可靠性不足**，本矩阵不据此登记任何状态，仅提示「2.0 加密算法族仍在扩展」。
2. **弃用清单**：XFA 表单、`NeedAppearances`、PostScript XObject、Procedure Sets、Movie/Sound 注解的部分用法，以及 `/Info` 中除 `CreationDate`/`ModDate` 之外的绝大多数键（XMP 成为文档级元数据唯一推荐来源）。「弃用」不等于「移除」：2.0 仍保留其语法以便读取历史文件——本库第 12/13/14 章相应条目的读端容忍策略不因 2.0 而改变。
3. **文本串**：新增 UTF-8 文本串写法（编码判定细节待核），**而非「Text string 统一为 UTF-8」**；UTF-16BE（含 BOM）与 PDFDocEncoding 在 2.0 中仍是合法表示。本库读端已按 32000-1 支持三种表示中的前两种（见 7.9.2.2 相关条目），UTF-8 属未登记缺口。
4. **日期格式**：日期串的 `D:` 前缀**不是** 2.0 新增的强制要求——ISO 32000-1:2008 原文即为「The prefix `D:` shall be present, the year field (YYYY) shall be present...」（本地全文 `pdftotext -raw` 抽取第 4284 行）。原表述「由可选变为强制」为评审纠正项。
5. **Associated Files**：`/AF` 与 `/AFRelationship` 纳入正文（实践源自 PDF/A-3），可挂接目录/页面/注解等多类字典；本库已在 14.1 与 F5/E6 条目登记读写端现状。
6. **附录与实现限制**：附录 D（实现限制）与多处澄清吸收进正文；**附录 F（线性化）在 2.0 中仍为规范性附录**，本库「线性化非目标」是设计决策而非「2.0 已删除附录 F」（见 ROADMAP 附录 F 条目）。
7. **Tagged PDF**：结构类型/属性目录扩展与命名空间机制增强无障碍语义，PDF/UA-2 改以机器可判定的规范声明表达无障碍要求（具体条目待核）。
8. **数字签名**：长期验证与时间戳支持增强（与 ETSI PAdES 交叉，细节待核）。
9. **纠正说明（2026-11-02 评审）**：本节原有「V=6/R=6」「文本串统一为 UTF-8」「`D:` 前缀由可选变强制」三处措辞已按上述更正；原第 9 条列出的输出意图新增 `/DestOutputProfileRef` 未能在权威来源核实（该键见于 PDF/X 与第三方实践讨论），已从本节删除。

**标准版本史与相关家族（登记用途：判断需求出处，不代表开发范围）**：

- **ISO 32000-1:2008**（PDF 1.7）：本矩阵与 ROADMAP 的规范骨架；其后重新发布为 LST ISO 32000-1:2009（内容等同），并有 Corrigendum 1:2009 与 Amendment 1:2012 两份修订/增补（不改变第 7–14 章章节体系，故矩阵不为其单列行）。本地权威副本 `docs/PDF32000_2008.pdf`。
- **ISO 32000-2**（PDF 2.0）：2017 首发，2020 重新发布（约 1002 页），并有 DAmd 1:2023（2023-04 发布的增补草案/修订，其正式状态待核）。即本节差异摘要的对象。
- **ISO 21757-1:2020**：PDF 中的 ECMAScript 子集（JavaScript 引擎要求的独立标准）。本库早先把它误记为「ISO/TS 32005」，2026-11-02 评审更正为 ISO 21757-1。
- **ISO 19005 系列（PDF/A）**：-4:2020 直接基于 PDF 2.0；-1/-2/-3 基于 PDF 1.x。
- **ISO 14289 系列（PDF/UA）**：-2:2024 基于 PDF 2.0。
- **ISO 15930 系列（PDF/X，预印）** 与 **ISO 16612 系列（PDF/VT，可变数据）**：与第 14.11 章预印支持条目相关，但一致性要求属各自标准。
