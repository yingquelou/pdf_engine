## 排序原则

1. **PDF 标准特性优先，扩展特性次之**：ISO 32000-1 必选/核心结构（文件结构、交叉引用、流、过滤器、字体、内容流、图形）优先于标准可选特性（注解、表单、透明、可选内容、结构树），后者优先于专用标准（3D、多媒体、签名）与厂商扩展（Adobe ExtensionLevel、`ADBE`、U3D/PRC）。
2. **读端正确性优先于写端覆盖面**：同一优先级内，先修复真实文件的可读性与错误恢复，再扩展可写特性。
3. **扩展特性不得挤占标准特性**：需要为扩展特性做取舍时，标准特性的读写完整性先保持；XFA 等非目标以 `non-goals.md` 为准。
4. **验证口径独立**：标准特性以“库写端生成 + 外部主流阅读器/工具核对”为主；读端异形文件由外部工具现场生成、只读、不入仓，详见 `backlog/fixtures.md`；读端鲁棒性验证的完整评估与落地顺序见 [robustness-verification.md](robustness-verification.md)。

## 进度跟踪约定

### 状态机

- 单条目状态：`⬜ → 🚧（进行中）→ ✅`；评审决定不做的转 `❌` 并注明理由。
- 矩阵条目的四态（✅/🟡/⬜/❌）与总状态合并规则以 `docs/matrix/README.md` 图例为准；矩阵条目由 `✅` 降为 `🟡` 必须在备注中写明缺口，并在矩阵「总览」修订记录中登记。
- 禁止 `✅ → ⬜` 回退；除非实现被移除，且须在矩阵备注中注明原因。增量条目与阶段状态的 `✅ → 🚧` 回退仅允许在验收口径修订时发生，并须在矩阵备注与本节「阶段映射」同时记录原因。
- 阶段状态：⬜ 未开始 / 🚧 进行中 / ✅ 完成 / ❌ 放弃。阶段完成后发现验收缺口时回退为 🚧，并记录缺口与补做增量（参见阶段 A 的 A6）。
- 状态只在代码实测后修改，禁止凭印象改动。

### 「完成」定义（三齐）

一个增量标记 ✅ 必须同时满足：

1. **代码实现合入**：功能代码进入主分支；
2. **有对应测试**：单元测试 + 必要的集成往返测试，测试名写入矩阵对应行；
3. **文档同步**：矩阵状态/证据/总览统计同步更新，必要时更新 README 版本特性速查表与本文件阶段状态。

三者缺一，不得标 ✅（至多标 🚧）。

### 更新流程（新目录树）

每次增量完成时按顺序执行：

1. **矩阵行**：改 `docs/matrix/chNN/<file>.md` 对应行的状态、Reader/Writer 分列与证据（测试名写证据列，不写数量）；
2. **矩阵总览**：运行 `scripts/docs_check.ps1`，按 C1 的实际计数更新 `docs/matrix/README.md` 总览，不手算；
3. **阶段文件**：勾选 `docs/roadmap/stages/<stage>.md` 对应增量复选框；阶段全部增量 ✅ 时，更新 `docs/roadmap/README.md` 阶段总览的「已完成/增量数」与状态；
4. **changelog**：在 `docs/changelog/YYYY-MM-DD.md` 追加当日条目（同一天同一文件，只追加、不改写历史条目）；测试数、行数、体积等易漂移数字只写这里或 `backlog/module-debt.md`、`backlog/fixtures.md`；
5. **门禁**：运行 `scripts/docs_check.ps1 -Strict` 确认 C1–C6 全过；归档目录 `docs/archive/` 不参与检查。

## 维护说明

- 本文件只写「计划、依赖、验收」，不复制测试名；测试证据以矩阵为准。
- 每次增量完成后更新阶段总览的「已完成」计数；若增量拆分/合并，先更新本文件再动代码。
- 新增条目必须给出 ISO 32000-1 章节号与矩阵行；章节号与表号以本地全文 `docs/PDF32000_2008.pdf` 为唯一权威，核对方法是 `pdftotext -raw` 抽取后按条款号/`Table N` 检索（**勿用 `-layout`**：多列表格会列错位，导致表号张冠李戴）。早先引用的 `docs/PDF32000_2008/`（HTML 导出目录）在本仓库不存在，2026-11-02 评审核查后已从两份规划文档的权威口径中删除；文首 2026-10-26 历史条目原文保留，不作为当前口径。
- 规划调整需在「阶段映射」或本文件顶部记录日期与原因，避免历史记忆与文档冲突。
