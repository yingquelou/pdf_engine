# 规范—规划—实现 三方一致性机制

> 状态：**已落地（P1–P3）**。索引、检查器、基线与注入式自测均已入库并在当前工作树运行通过；实测数据见 5.2，注入结论见第 8 节。
> 职责：定义「规范条款 ↔ 规划条目 ↔ 代码实现」的可机械判定规则、数据落位、检查项编号与失败语义。
> 边界：只约束 `docs/` 与 `scripts/`。不修改矩阵 `ch*/` 内容行、`docs/changelog/`、`scripts/deps.allow.toml`、`src/`、`Cargo.toml`。
> 与既有门禁的关系：`scripts/docs_check.ps1`（C1–C8）查文档自洽，`scripts/deps_check.ps1`（D1–D9）查依赖；本机制查**跨层引用是否真实**，三者不重叠（见第 7 节）。
> 日常检查离线、只读：`powershell -File scripts/spec_check.ps1`；门禁加 `-Strict`；重建比对加 `-RebuildVerify`；执行注入自测加 `-RunTests`。

## 1. 事故与要防的四类漂移

真实事故：规划条目要求实现「图像字典的 `/Matrix` / 设备映射」。ISO 32000-1 的 §8.9.5 Table 89 图像字典没有 `/Matrix`；图像到单位正方形的映射由 `Do` 与 CTM 承担，`/Matrix` 属 §8.10.2 Form XObject。照做等于凭空发明非标准键。

| 类别 | 典型表现 | 拦截项 |
|---|---|---|
| 1 规范锚点缺失或伪造 | 条目没有条款号；或写了本地规范中不存在的条款/表；或条款里没有条目涉及的键 | S1、S2、S3、S4 |
| 2 规划 → 实现单向无回执 | 规划 `[x]` 后，矩阵里找不到对应行或行仍是 ⬜ | S5 |
| 3 证据失效 | 反引号里的测试名、模块路径、符号名已改名或删除 | S6、S7 |
| 4 状态虚报 | 矩阵标 ✅，但证据符号/测试不存在，或测试不通过 | S6、S8 |

**能力边界（必须明说）**：本机制保证的是**必要条件**——键名必须出现在所引条款/表的文本里，证据必须真实存在，状态必须有回执。它不能自动判断「引用的条款是否语义正确」。把图像条目错误地锚到 §8.10.2 仍可能通过 S4；这类错误由矩阵行覆盖（S5）与评审承担。机制的目标是让「凭空发明键」和「文档说做了、代码没做」无法悄悄发生。

## 2. 判定规则

### 2.1 规范锚点

可接受形式：

- 小节号：`8.9.5`、`12.5.6.15`、`7.3.8`。
- 范围：`8.9.2–8.9.4`（连接符接受 `–`、`—`、`-`）；两端必须存在，中间已有的小节自动展开。
- 章级：`第 10 章`。
- 附录：`附录 F`、`Annex F`。
- 表：`Table 89`（大小写不敏感），并映射到其所属小节。

不接受：`11.x` 之类通配、两位版本号（如 `1.7`）、没有数字的「见相关章节」。

锚点归属：

| 文档单元 | 锚点来源 |
|---|---|
| 矩阵 A 型行（8 列及以上，含「章节」列） | 第一列「章节」；为空或不可解析即失败 |
| 矩阵 B 型行（7 列，第一列为「注解类型」等） | 文件 H1 标题里的条款范围 ∪ 行内显式条款号 ∪ 行内 `Table N` 所属小节 |
| 规划复选框条目 | 复选框首行的条款/表号；新条目必须使用 `（规范：…）` 标记 |
| 非规范条目（纯工程/流程项） | 必须写 `（非规范：依据）`，依据须能归类为 工程决策 / 内部约定 / 其他规范+条款号；仅允许出现在规划条目，矩阵行禁止；见 4.1 |

### 2.2 键名

- 参与溯源的键名只认反引号内的 `/Name`（如 `` `/Matrix` ``），大小写敏感、词边界匹配。
- 单元的有效文本范围 = 所引每个条款的正文窗口 ∪ 行内引用的每张表的窗口。
  - 条款窗口：从标题行到下一个**同级或更浅**的标题；子节与表包含在内。
  - 表窗口：从表标题到下一个标题或下一张表；`(continued)` 续表并入同一窗口。
- 判定：键名必须至少在一个窗口内以 `/Name` 或独立词 `Name` 出现；否则报「键不在所引条款/表内」。
- 已知弱点：`Length`、`Type` 这类常用词可能因正文出现而误通过；只写名字不带 `/` 的键不参与溯源（工程约定要求键名带 `/`）。因此这是必要条件，不是充分条件。

### 2.3 回执与状态

- 矩阵行是状态与证据的唯一存放处；规划条目只写范围、依赖与验收，不复制测试名。
- 规划条目 → 矩阵行：按锚点覆盖关系解析。行锚点等于条目锚点、范围包含条目锚点、或行锚点是小节前缀，均算覆盖（`8.9.5` 覆盖 `8.9.5.2`）。
- 规划 `[x]` → 每个锚点至少命中一行，且命中行状态为 ✅ 或 🟡；只命中 ⬜/❌ 视为无回执。
- 矩阵 ✅ 行 → 证据列至少有一个可解析的测试名、一个可解析的实现符号；测试执行由 S8 可选校验。
- 矩阵 🟡 行 → 证据列至少有一个可解析的符号或测试名（部分实现允许部分证据）。
- 证据 token 分类与解析：
  - `*.rs` 路径（含 `{a,b}` 展开）→ 文件或目录模块存在。
  - 模块路径（`reader/annotation/mk`）→ 对应 `src/`/`tests/` 下的文件或目录存在。
  - 符号（`Type::member`、`crate::path::fn()`、CamelCase/snake_case 标识符）→ 定义索引命中（`fn`/`struct`/`enum`/`trait`/`type`/`const`/`static`/`mod`/枚举变体/结构字段）。
  - 测试名 → 测试函数集合命中；S8 追加「已通过」校验。
- 避免与 docs_check 重复：矩阵证据里的 `*.rs` 路径存在性归 C2；S7 只查矩阵里的非路径符号/测试名，以及规划条目里的全部代码引用。

### 3.1 索引生成

1. 探测 Ghostscript：依次查找 `gswin64c`、`gswin32c`、`gs`；记录实际路径与版本。
2. 抽取：`gswin64c -q -dNOPAUSE -dBATCH -sDEVICE=txtwrite -sOutputFile=<txt> docs/PDF32000_2008.pdf`。
3. 归一化：仅统一换行为 LF，不改写空白、不重排文本，保证可人工审计。
4. 计算 `source_sha256`、`text_sha256`、章节/表数量，写入 `meta.json`。
5. 写入前校验**哨兵**（第 6 节）；哨兵不成立则拒绝写入并报错。

抽取是离线一次性动作，实测约 80 秒，产物约 3.4 MiB。抽取文本与 `docs/PDF32000_2008.pdf` 同一内部用途、同一入库范围，不对外分发。

### 3.2 缓存与失效

- `iso32000-1.txt` 就是缓存，随仓库提交，日常检查不依赖 Ghostscript、不联网。
- 失效判定（S1）：`meta.source_sha256` 与当前 PDF 不一致，或 `meta.text_sha256` 与实际文本不一致 → FAIL，并打印重建命令。
- 重建比对（S2）：有 Ghostscript 时重新抽取并与仓库索引做**语义比对**（标题集合、表号→所属小节、哨兵结果），不要求字节一致；版本差异导致空白变化不算失败。无 Ghostscript → SKIP 并列出查找过的路径。
- 换版：源 PDF 哈希变化后，生成器打印哨兵差异并要求人工复核。确认是标准换版后，人工更新 `meta.json` 的哨兵与本文件第 6 节，再重建；不允许只改哈希绕过。

## 4. 检查项 S1–S8

| 编号 | 名称 | 规则 | FAIL 含义 |
|---|---|---|---|
| S1 | 索引完整性与防篡改 | 文本与元数据存在；`text_sha256` 匹配；条款 7–14 与表数量达到结构下限；哨兵全部成立；PDF 存在时校验 `source_sha256` | 索引被手改、过期或抽取错误 |
| S2 | 索引可重建 | 有 Ghostscript 时重建并语义比对；不一致即失败 | 仓库索引与 PDF 事实不符 |
| S3 | 规范锚点可解析 | 所有矩阵行、规划条目按 2.1 解析；不存在的条款/表、通配、空锚点均失败；非规范条目见 4.1 | 锚点缺失或伪造 |
| S4 | 键名溯源 | 按 2.2 校验每个反引号 `/Key` | 发明了所引条款/表里不存在的键 |
| S5 | 规划 → 矩阵回执 | 每个条目的锚点覆盖到矩阵行；`[x]` 的命中行不得全是 ⬜/❌ | 规划完成但矩阵无回执 |
| S6 | 矩阵 → 实现回执 | ✅/🟡 行的证据必须声明符号与测试（强度按 2.3） | 声称实现却没有证据 |
| S7 | 证据 token 命中 | 按 2.3 解析路径、模块、符号、测试名；未命中即失败 | 证据指向已改名/删除的对象 |
| S8 | 测试执行 | `-RunTests` 运行测试或读取 `-TestResults`；✅ 行声明的测试必须在通过列表 | 证据存在但测试不通过 |

状态语义：

- **PASS**：没有未登记的违规；若有基线项，摘要与 JSON 明确显示基线数量，详情前缀 `[基线]`。
- **FAIL**：存在未登记违规，或基线条目已失效（对应违规已不存在）。
- **SKIP**：仅用于外部能力缺失（S2 无 Ghostscript、S8 未提供测试结果），必须列出已尝试的路径/命令。**不得**用 SKIP 掩盖仓库内可判定的事实。
- 退出码：`-Strict` 且存在 FAIL → 1；SKIP 不计入失败（与 `deps_check` 一致）。
- 输出对齐既有脚本：`-Root`、`-Strict`、`-Json`、`-DetailLimit`；JSON 增加 `skipped`、`baselined`、`staleBaseline` 计数。

### 4.1 非规范标记（S3.1–S3.5）

纯工程/流程条目没有规范依据，不能硬造锚点，也不应长期占用基线。写法：

```
- [ ] **A6 真实样本回归**（非规范：工程决策）
- [ ] **C1 …**（非规范：内部约定，见 docs/roadmap/principles.md）
- [ ] **X1 …**（非规范：遵循 ISO 32000-2 §8.9）
```

| 编号 | 规则 | FAIL 含义 |
|---|---|---|
| S3.1 | 标记必须带依据，且能归类为 工程决策 / 内部约定 / 其他规范+条款号；`（非规范）`、`（非规范：）` 等空依据一律 FAIL | 用空标记绕过锚点 |
| S3.2 | 依据合规且条目无可解析锚点 → S3 判 PASS，并记入「非规范条目清单」 | — |
| S3.3 | 反滥用：带标记但条目文本仍能解析出索引中的条款/表 → FAIL | 标记不是免死金牌 |
| S3.4 | 标记只允许出现在 `docs/roadmap/` 阶段条目；矩阵行出现标记即 FAIL | 矩阵行必须对得上规范 |
| S3.5 | 非规范条目总数上限 20；超限 FAIL 并要求人工复核 | 防止标记扩散架空机制 |

清单同时进入 `-Json` 的 `nonSpec`（`limit` / `count` / `items`）与文本模式的 S3 详情（前缀 `[非规范]`）；`-Strict` 与日常检查行为一致。

## 5. 基线与分批

### 5.1 基线格式

`scripts/spec.baseline.toml` 采用 `deps.allow.toml` 同风格的最小 TOML：

```toml
[[violation]]
check = "S4"
file = "docs/matrix/ch12/annotations/media-form-prepress.md"
unit = "Widget"
anchor = ""
key = "AP"
reason = "B 型行未给出自身小节，锚点来自所属文件；待补锚点"
since = "2026-11-07"
```

约束：

- 匹配必须精确到 `check + file + unit + key`；`unit` 是矩阵行标识（章节或注解类型）或规划条目编号。
- `reason` 不得为空；`since` 记录登记日期。
- 基线项在对应违规消失后即为**失效**，S1–S8 任一检查发现失效基线即 FAIL，要求删除，防止基线变成永久豁免。
- 不提供按文件、按目录的白名单；非规范条目也必须逐条登记理由。

## 6. 反绕过设计

1. **索引防篡改**：`meta.json` 固定源 PDF 哈希与文本哈希；S1 每次校验。手改文本或元数据都会 FAIL。
2. **哨兵事实**：`meta.json` 记录少量不可协商的检索事实，生成器与检查器都校验：
   - §8.9.5 的正文与 Table 89 **不含** `Matrix`；
   - §8.10.2 与 Table 95 **含** `Matrix`；
   - §8.9.5 **含** `Width`。
   把 `Matrix` 塞进 8.9.5 的索引以「洗白」伪造键，会先触发 S1。
3. **锚点必须可重建**：S2 用原 PDF 重建后比对标题集合与表归属；索引不能只靠手写 JSON 维持。
4. **键名书写约定**：工程约定要求键名写成 `/Name`；不带 `/` 的名字不参与溯源。删除 `/` 逃避检查属于文档违规，评审可见，且 S6/S7 仍要求证据真实。
5. **基线不可滥用**：精确匹配、必须写理由、失效即 FAIL；不提供文件级豁免。
6. **检查器自身**：规则只写在 `principles.md` 与本文件；修改检查器需评审；`scripts/spec_check.selftest.ps1` 固化注入用例，防止后续改动把判定悄悄放宽。
7. **SKIP 受限**：仅外部工具缺失可 SKIP；仓库内事实不可 SKIP。

## 8. 注入式验证（可复现证明）
